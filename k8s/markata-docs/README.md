# Markata documentation hosting

Argo CD combines this homelab overlay with the `helm-chart` in
`WaylonWalker/markata`. The Markata chart runs the real Markata Go builder and
Builder Admin; the Python-Markdown builder and dedicated docs images have been
retired.

- **Public site:** https://markata.waylonwalker.com and https://markata.dev
- **Protected Builder Admin:** https://build.markata.waylonwalker.com
- **Source:** public `WaylonWalker/markata` `main` branch
- **Site config:** `/data/source/markata-docs.toml`
- **Builder:** Markata Helm chart `builder-admin` with signed GitHub Push webhook
- **Source checkout:** chart-managed persistent source PVC, initialized from Git
- **Published releases:** existing `markata-docs-site` Longhorn PVC (preserved)
- **Public replicas:** chart-managed nginx serving the current retained release
- **Protected previews:** `/__preview/<release>/` through the chart's Builder Admin auth middleware
- **Node:** `falcon3`, because the site PVC is ReadWriteOnce

On first startup, the chart initializes its Git checkout from the public repo.
GitHub Push events to `main` reach
`https://build.markata.waylonwalker.com/webhook`; Builder Admin verifies the
HMAC, fast-forwards the checkout, and queues a normal Markata build. Failed
builds leave the current public release in place.

## Before rollout

1. Confirm the Markata Docker workflow published the builder image pinned in
   `helm-values.yaml` (`sha-5017ab5`) before allowing Argo to reconcile.
2. Create the `markata-docs-builder-webhook` Kubernetes Secret in namespace
   `markata-docs`. It must contain a `webhook-secret` key with a random HMAC
   secret. Keep the value out of Git.
3. Add a GitHub repository webhook for Push events at the URL above. Set the
   same HMAC secret and use JSON payloads.
4. Validate the Argo manifests and Helm output. Argo CD will reconcile the
   `markata-docs` Application after this change merges.

## Verify rollout

```bash
kubectl kustomize k8s/markata-docs/
kubectl -n argocd get application markata-docs
kubectl -n markata-docs get pvc,pods,svc,ingress
kubectl -n markata-docs logs deployment/markata-docs-notes-builder-admin --tail=100
kubectl -n markata-docs rollout status deployment/markata-docs-notes-site
curl -fsSI https://markata.dev/
curl -fsSI https://markata.dev/docs/guides/authoring/
```

The public ingress remains homelab-managed so both domains retain their current
certificates. It routes to the chart's `markata-docs-notes-site` service.
Builder Admin's protected ingress and webhook route are generated by the chart.

Do not run the historical docs builder Deployment or
`kubernetes/markata-go-docs.yaml` CronJob. Both bypass the Markata chart and
release workflow.
